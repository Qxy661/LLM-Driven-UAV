## 2. 单元测试

### 2.1 LLM 输出测试

```python
import pytest
from llm_uav.intent_parser import IntentParser

class TestIntentParser:
    """意图解析器单元测试"""

    def setup_method(self):
        self.parser = IntentParser(mock_llm_client)

    def test_takeoff_intent(self):
        result = self.parser.parse("起飞到20米")
        assert result["intent"] == "takeoff"
        assert result["parameters"]["altitude"] == 20

    def test_goto_intent(self):
        result = self.parser.parse("飞到教学楼A")
        assert result["intent"] == "goto_location"
        assert "教学楼A" in result["parameters"]["target"]

    def test_ambiguous_input(self):
        result = self.parser.parse("看看那边")
        assert result["confidence"] < 0.7
        assert result.get("ambiguity") is not None

    def test_safety_violation(self):
        result = self.parser.parse("飞到150米高度")
        assert result["safety_flags"]["altitude_exceeded"] == True

    def test_invalid_input(self):
        result = self.parser.parse("今天天气真好")
        assert result["is_valid_command"] == False
```

## 3. 集成测试

### 3.1 ROS2 集成测试

```python
import rclpy
from rclpy.node import Node
import unittest

class TestLLMIntegration(unittest.TestCase):
    """LLM 集成测试"""

    def setUp(self):
        rclpy.init()
        self.node = rclpy.create_node('test_node')

    def test_voice_to_task_flow(self):
        """测试语音到任务的完整流程"""
        # 发布语音指令
        pub = self.node.create_publisher(String, 'voice/command', 10)
        msg = String()
        msg.data = "起飞到20米"
        pub.publish(msg)

        # 等待任务计划输出
        received = []
        sub = self.node.create_subscription(
            String, 'llm/task_plan',
            lambda m: received.append(m.data), 10
        )

        # 等待超时
        timeout = 10.0
        start = time.time()
        while len(received) == 0 and time.time() - start < timeout:
            rclpy.spin_once(self.node, timeout_sec=0.1)

        assert len(received) > 0
        task = json.loads(received[0])
        assert task["steps"][0]["action"] == "takeoff"
```

## 4. 仿真测试

### 4.1 Gazebo 仿真

```python
class GazeboSimulationTest:
    """Gazebo 仿真测试"""

    def __init__(self):
        self.world = "empty_world"  # 或自定义世界
        self.uav_model = "iris"     # PX4 默认模型

    def test_basic_flight(self):
        """基本飞行测试"""
        # 启动仿真
        self.launch_simulation()

        # 等待 PX4 就绪
        self.wait_for_px4()

        # 执行起飞指令
        result = self.execute_command("起飞到10米")
        assert result["success"] == True

        # 验证高度
        altitude = self.get_altitude()
        assert 9.5 <= altitude <= 10.5

    def test_obstacle_avoidance(self):
        """避障测试"""
        self.launch_simulation(world="obstacle_world")

        # 执行前进指令
        result = self.execute_command("向前飞50米")

        # 验证是否避开了障碍物
        assert result["collision"] == False

    def test_mission_execution(self):
        """任务执行测试"""
        self.launch_simulation()

        # 执行复杂任务
        result = self.execute_command("巡逻A区域，拍照并返回")

        assert result["success"] == True
        assert result["photos_taken"] > 0
        assert result["returned_home"] == True
```

## 6. 测试自动化

### 6.1 CI/CD 集成

```yaml
# .github/workflows/test.yml
name: LLM-UAV Tests

on: [push, pull_request]

jobs:
  unit-tests:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: Setup Python
        uses: actions/setup-python@v4
        with:
          python-version: '3.10'
      - name: Install dependencies
        run: pip install -r requirements.txt
      - name: Run unit tests
        run: pytest tests/unit/

  integration-tests:
    runs-on: ubuntu-latest
    needs: unit-tests
    steps:
      - uses: actions/checkout@v3
      - name: Setup ROS2
        uses: ros-tooling/setup-ros@v0.6
      - name: Run integration tests
        run: pytest tests/integration/

  simulation-tests:
    runs-on: ubuntu-latest
    needs: integration-tests
    steps:
      - uses: actions/checkout@v3
      - name: Setup Gazebo
        run: sudo apt install gazebo
      - name: Run simulation tests
        run: pytest tests/simulation/
```

## 思考题

1. LLM 输出的不确定性如何影响测试策略？
2. 如何设计测试用例以覆盖 LLM 的各种可能输出？
3. 仿真测试和实机测试的差距如何弥合？
4. 如何评估 LLM 在安全关键场景中的可靠性？
5. 设计一个完整的 LLM 无人机系统测试方案。

<details>
<summary>参考答案</summary>

**1.** LLM 输出不确定性的影响：(1) 同一输入可能产生不同输出 — 需要多次测试统计成功率；(2) 难以定义精确的期望输出 — 需要模糊匹配或语义比较；(3) 边界情况难以覆盖 — 需要大量多样化测试用例。应对策略：(1) 使用 temperature=0 减少随机性；(2) 测试输出的语义而非精确文本；(3) 使用对抗性测试用例。

**2.** 测试用例设计：(1) 正常用例 — 常见指令的正确解析；(2) 边界用例 — 最大/最小参数值；(3) 异常用例 — 模糊、矛盾、无效输入；(4) 安全用例 — 违反安全约束的指令；(5) 对抗用例 — 提示注入攻击。

**3.** 弥合差距：(1) 仿真中使用真实的 LLM（非模拟）；(2) 在仿真中模拟真实环境（风、光照变化）；(3) 使用真实传感器数据回放；(4) 仿真通过后在安全环境中做小规模实机验证；(5) 逐步增加实机测试的复杂度。

**4.** 评估方法：(1) 故障注入测试 — 故意引入异常场景；(2) 压力测试 — 高负载下的表现；(3) 安全审计 — 人工审查 LLM 的决策链；(4) 对比测试 — LLM vs 规则引擎在相同场景下的表现；(5) 统计评估 — 大量测试用例的成功率和错误类型分析。

**5.** 完整方案：(1) 定义测试策略和通过标准；(2) 编写单元测试（LLM输出、安全检查）；(3) 编写集成测试（节点通信、数据流）；(4) 设计仿真场景（正常、异常、边界）；(5) 执行自动化测试（CI/CD集成）；(6) 实机验证（渐进式）；(7) 持续回归测试。

</details>
