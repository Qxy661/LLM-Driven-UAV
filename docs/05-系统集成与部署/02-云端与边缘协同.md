### 1.2 任务分配原则

| 任务类型 | 执行位置 | 原因 |
|---------|---------|------|
| 实时避障 | 边缘 | 延迟要求 <10ms |
| 简单指令理解 | 边缘 | 低延迟，离线可用 |
| 复杂任务规划 | 云端 | 需要大模型推理能力 |
| 图像详细分析 | 云端 | 需要大 VLM |
| 场景快速理解 | 边缘 | 实时性要求 |
| 历史数据分析 | 云端 | 数据量大 |
| 紧急决策 | 边缘 | 不依赖网络 |

## 2. 任务路由

### 2.1 智能路由策略

```python
class TaskRouter:
    """任务路由器 — 决定在云端还是边缘执行"""

    def __init__(self, edge_client, cloud_client):
        self.edge = edge_client
        self.cloud = cloud_client
        self.network_monitor = NetworkMonitor()

    def route_and_execute(self, task):
        """路由并执行任务"""
        # 评估任务复杂度
        complexity = self._assess_complexity(task)

        # 检查网络状态
        network = self.network_monitor.get_status()

        # 决策
        if complexity == "high" and network["available"]:
            return self._execute_cloud(task)
        elif complexity == "low":
            return self._execute_edge(task)
        elif network["available"]:
            return self._execute_cloud_with_edge_fallback(task)
        else:
            return self._execute_edge(task)

    def _assess_complexity(self, task):
        """评估任务复杂度"""
        # 简单规则：基于任务类型和输入长度
        if task.get("type") in ["simple_command", "status_check"]:
            return "low"
        elif len(task.get("prompt", "")) > 500:
            return "high"
        else:
            return "medium"

    def _execute_cloud_with_edge_fallback(self, task):
        """云端执行，边缘降级"""
        try:
            result = self.cloud.execute(task, timeout=5.0)
            return result
        except TimeoutError:
            return self._execute_edge(task)
```

## 3. 延迟管理

### 3.1 延迟预算

```
总延迟预算: 200ms (用户可接受)

分配:
├── 网络传输: 50ms (上行) + 50ms (下行)
├── 云端推理: 100ms
├── 边缘处理: 20ms
└── 余量: -20ms (超出预算)

结论: 复杂任务需要 >200ms，应使用边缘降级
```

### 3.2 预测性推理

```python
class PredictiveInference:
    """预测性推理 — 提前计算可能需要的结果"""

    def __init__(self, edge_client, cloud_client):
        self.edge = edge_client
        self.cloud = cloud_client
        self.prediction_cache = {}

    def predict_next_action(self, current_state, task_context):
        """预测下一步可能需要的动作"""
        # 在空闲时预先计算
        prompt = f"""基于当前状态和任务上下文，预测下一步可能需要的3个动作。

当前状态: {current_state}
任务上下文: {task_context}

输出 JSON 格式的预测列表。"""

        predictions = self.cloud.generate(prompt)

        # 预先缓存结果
        for pred in predictions:
            cache_key = self._make_cache_key(pred)
            self.prediction_cache[cache_key] = self._precompute(pred)

    def get_cached_result(self, action):
        """获取缓存的预计算结果"""
        cache_key = self._make_cache_key(action)
        return self.prediction_cache.get(cache_key)
```

## 4. 离线模式

### 4.1 离线能力设计

```python
class OfflineCapability:
    """离线模式管理"""

    def __init__(self, edge_model, cache_db):
        self.edge_model = edge_model
        self.cache = cache_db
        self.offline_rules = {
            "takeoff": self._rule_takeoff,
            "land": self._rule_land,
            "return_to_home": self._rule_rtl,
            "hover": self._rule_hover,
        }

    def handle_offline(self, command):
        """处理离线模式下的命令"""
        # 1. 检查是否有规则处理
        if command["intent"] in self.offline_rules:
            return self.offline_rules[command["intent"]](command)

        # 2. 检查缓存
        cached = self.cache.get(command["text"])
        if cached:
            return cached

        # 3. 使用边缘模型
        return self.edge_model.generate(command["text"])

    def _rule_takeoff(self, command):
        altitude = command.get("params", {}).get("altitude", 10)
        altitude = min(altitude, 30)  # 离线模式限制高度
        return {"action": "takeoff", "altitude": altitude}

    def _rule_rtl(self, command):
        return {"action": "return_to_home"}
```

## 5. 同步与一致性

### 5.1 状态同步

```python
class StateSyncManager:
    """状态同步管理器"""

    def __init__(self, edge_state, cloud_state):
        self.edge = edge_state
        self.cloud = cloud_state
        self.sync_interval = 10  # 秒

    def sync_to_cloud(self):
        """将边缘状态同步到云端"""
        state = self.edge.get_full_state()
        try:
            self.cloud.update_state(state)
        except NetworkError:
            # 网络不可用时缓存，等网络恢复后同步
            self._queue_for_sync(state)

    def sync_from_cloud(self):
        """从云端获取更新"""
        try:
            updates = self.cloud.get_updates(self.edge.last_sync_time)
            self.edge.apply_updates(updates)
        except NetworkError:
            pass  # 使用本地缓存
```

## 思考题

1. 如何决定一个任务应该在云端还是边缘执行？
2. 在网络完全中断的情况下，如何保证无人机仍能安全完成任务？
3. 如何优化云边协同的延迟？
4. 边缘模型和云端模型的能力差距如何弥补？
5. 设计一个完整的云边协同无人机系统架构。

<details>
<summary>参考答案</summary>

**1.** 决策因素：(1) 延迟要求 — 实时任务在边缘，非实时在云端；(2) 复杂度 — 需要大模型推理的在云端；(3) 网络状态 — 网络差时在边缘；(4) 安全性 — 安全关键任务在边缘（不依赖网络）；(5) 数据量 — 大数据处理在云端。

**2.** 策略：(1) 边缘模型处理简单任务；(2) 预定义规则处理常见场景；(3) 预缓存可能需要的结果；(4) 安全操作（起飞、降落、返航）硬编码实现；(5) 限制离线模式的飞行范围和任务复杂度。

**3.** 优化策略：(1) 减少传输数据量（压缩、只传关键信息）；(2) 使用更快的网络（5G）；(3) 预测性推理（提前计算）；(4) 结果缓存（避免重复推理）；(5) 边缘预处理（只将复杂部分发到云端）。

**4.** 弥补策略：(1) 知识蒸馏 — 用云端大模型训练边缘小模型；(2) 任务分解 — 大任务拆分成小任务，小任务用边缘模型；(3) 云端辅助 — 边缘模型不确定时请求云端确认；(4) 持续更新 — 定期将云端模型的知识同步到边缘。

**5.** 完整架构：(1) 云端层 — 大模型推理、任务管理、数据分析、模型更新；(2) 传输层 — 4G/5G/卫星链路、数据压缩、加密；(3) 边缘层 — 小模型推理、实时控制、传感器处理；(4) 控制层 — 飞控系统、安全约束；(5) 管理层 — 任务路由、状态同步、故障处理。

</details>
