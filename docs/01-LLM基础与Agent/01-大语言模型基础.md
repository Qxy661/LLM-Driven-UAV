## 1. 从 RNN 到 Transformer

### 1.1 序列建模的演进

语言模型的核心任务是**对文本序列建模**，预测下一个 token。早期方案存在明显瓶颈：

| 模型 | 年份 | 核心思想 | 主要局限 |
|------|------|---------|---------|
| N-gram | 1990s | 统计相邻词共现频率 | 无法捕捉长距离依赖 |
| RNN | 2013 | 循环结构记忆历史信息 | 梯度消失/爆炸，训练慢 |
| LSTM | 2015 | 门控机制缓解梯度问题 | 仍为串行计算，长序列困难 |
| Transformer | 2017 | 自注意力并行处理全局信息 | 计算复杂度 O(n²)，但可并行 |

### 1.2 Transformer 架构

Transformer（Vaswani et al., 2017）是当前所有主流 LLM 的基础架构：

```
输入序列: ["无", "人", "机", "飞", "行"]

┌─────────────────────────────────┐
│       Embedding + Positional    │  ← 词嵌入 + 位置编码
├─────────────────────────────────┤
│    ┌───────────────────────┐    │
│    │   Multi-Head Attention │    │  ← 多头自注意力
│    └───────────┬───────────┘    │
│           Add & Norm            │  ← 残差连接 + 层归一化
│    ┌───────────────────────┐    │
│    │   Feed-Forward Network │    │  ← 前馈神经网络
│    └───────────┬───────────┘    │
│           Add & Norm            │
│          × N layers             │  ← 重复 N 层
├─────────────────────────────────┤
│         Output Head             │  ← 预测下一个 token
└─────────────────────────────────┘
```

**关键创新点**：

1. **自注意力（Self-Attention）**：每个 token 都能直接"看到"序列中所有其他 token，无需像 RNN 那样逐步传递信息
2. **并行计算**：整个序列同时处理，大幅加速训练
3. **位置编码（Positional Encoding）**：通过正弦/余弦函数编码位置信息

## 2. 注意力机制详解

### 2.1 缩放点积注意力

自注意力的核心公式：

$$
\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right) V
$$

其中：
- **Q (Query)**：当前 token 想要"查询"的信息
- **K (Key)**：每个 token 提供的"索引"信息
- **V (Value)**：每个 token 携带的实际内容
- **$\sqrt{d_k}$**：缩放因子，防止点积过大导致 softmax 梯度消失

### 2.2 多头注意力

单一注意力头只能捕捉一种类型的关联。多头注意力让模型同时关注不同类型的关系：

```
输入 X
  │
  ├─→ Head 1 (关注语法关系) ─→ 输出 1
  ├─→ Head 2 (关注语义关联) ─→ 输出 2
  ├─→ Head 3 (关注位置关系) ─→ 输出 3
  └─→ Head h (关注其他模式) ─→ 输出 h
  │
  Concat → Linear → 最终输出
```

**以无人机场景为例**：

在处理指令"飞到红色建筑旁边然后悬停"时：
- Head 1 可能关注"红色"与"建筑"的修饰关系
- Head 2 可能关注"飞到"与"悬停"的时序关系
- Head 3 可能关注"旁边"这一空间约束

### 2.3 因果注意力掩码

LLM 作为自回归模型，在预测第 t 个 token 时只能看到前 t-1 个 token：

```
Token:    无  人  机  飞  行
注意力矩阵:
  无  [  1   0   0   0   0 ]
  人  [  1   1   0   0   0 ]
  机  [  1   1   1   0   0 ]
  飞  [  1   1   1   1   0 ]
  行  [  1   1   1   1   1 ]

1 = 可以看到, 0 = 不可以看到（被 mask）
```

这种因果掩码（Causal Mask）确保模型在训练和推理时保持一致的自回归特性。

## 3. 预训练范式

### 3.1 预训练目标

LLM 的预训练通常采用**因果语言建模（Causal Language Modeling, CLM）**：

给定前缀序列 $x_1, x_2, ..., x_{t-1}$，预测下一个 token $x_t$：

$$
\mathcal{L} = -\sum_{t=1}^{T} \log P(x_t | x_1, ..., x_{t-1}; \theta)
$$

通过在海量文本（数万亿 token）上最小化这一损失，模型学会了：
- 语法结构和语言规律
- 世界知识和常识推理
- 逻辑推理和问题解决能力

### 3.2 主流预训练模型对比

| 模型 | 参数量 | 训练数据 | 上下文长度 | 开源 |
|------|--------|---------|-----------|------|
| GPT-4 | ~1.8T (传闻) | 未公开 | 128K | 否 |
| Llama 3.1 | 8B/70B/405B | 15T tokens | 128K | 是 |
| Qwen-2.5 | 0.5B-72B | 18T tokens | 128K | 是 |
| Mistral Large | 123B | 未公开 | 128K | 是 |
| DeepSeek-V3 | 671B (MoE) | 14.8T tokens | 128K | 是 |

### 3.3 Scaling Law

Kaplan et al. (2020) 发现的缩放定律表明，模型性能与以下因素呈幂律关系：

```
性能 ∝ N^α × D^β × C^γ

N = 模型参数量
D = 训练数据量
C = 计算预算
α ≈ 0.076, β ≈ 0.095, γ ≈ 0.050
```

这意味着：**增大模型、增加数据、增加计算，都能持续提升性能**。这一发现驱动了 LLM 领域的"军备竞赛"。

## 4. 微调技术

### 4.1 全量微调 vs 参数高效微调

| 方法 | 参数更新量 | 计算需求 | 效果 | 适用场景 |
|------|-----------|---------|------|---------|
| 全量微调 | 100% | 极高 | 最好 | 大公司、充足资源 |
| LoRA | 0.1-1% | 低 | 接近全量 | 个人/小团队 |
| QLoRA | 0.1-1% | 极低 | 略低于 LoRA | 资源受限 |
| Prefix Tuning | <0.1% | 极低 | 一般 | 特定任务 |
| Adapter | 1-5% | 低 | 良好 | 多任务切换 |

### 4.2 LoRA：低秩适配

LoRA（Low-Rank Adaptation, Hu et al., 2021）的核心思想：

```
原始权重 W ∈ R^{d×d}  (冻结不动)

新增低秩分解:
  W' = W + ΔW = W + B × A

其中 B ∈ R^{d×r}, A ∈ R^{r×d}, r << d

训练时只更新 A 和 B (极少量参数)
推理时可将 ΔW 合并回 W (无额外开销)
```

**无人机场景中的应用**：可以用 LoRA 为不同的无人机型号、不同的任务场景分别训练适配器，快速切换。

### 4.3 无人机领域微调示例

```python
# 使用 LoRA 微调 Llama 3 用于无人机任务理解
from peft import LoraConfig, get_peft_model
from transformers import AutoModelForCausalLM

# 加载基础模型
model = AutoModelForCausalLM.from_pretrained("meta-llama/Llama-3-8B")

# 配置 LoRA
lora_config = LoraConfig(
    r=16,                    # 低秩维度
    lora_alpha=32,           # 缩放因子
    target_modules=["q_proj", "v_proj"],  # 只对注意力层适配
    lora_dropout=0.05,
    bias="none",
    task_type="CAUSAL_LM"
)

# 应用 LoRA
model = get_peft_model(model, lora_config)
print(f"可训练参数: {model.print_trainable_parameters()}")
# 输出: 可训练参数: 4,194,304 || 总参数: 8,030,261,248 || 可训练比例: 0.052%
```

## 5. RLHF 对齐

### 5.1 为什么需要对齐？

预训练模型的目标是"预测下一个 token"，但这不等于"对用户有帮助"。未经对齐的模型可能会：
- 生成有害或不当内容
- 不遵循用户指令
- 编造事实（幻觉）

### 5.2 RLHF 三阶段

```
阶段 1: 监督微调 (SFT)
  └─ 用人工标注的高质量对话数据微调模型

阶段 2: 训练奖励模型 (RM)
  └─ 人类对比标注 → 训练一个评分模型

阶段 3: 强化学习优化 (PPO)
  └─ 用奖励模型的分数作为奖励信号
  └─ 用 PPO 算法优化语言模型策略
```

### 5.3 替代方案：DPO

DPO（Direct Preference Optimization, Rafailov et al., 2023）简化了 RLHF 流程：

```
传统 RLHF:  SFT → 训练 RM → PPO 优化  (三阶段，复杂)
DPO:        SFT → 直接用偏好数据优化   (两阶段，简单)

DPO 损失函数:
L = -log σ(β × [log π(y_w|x)/π_ref(y_w|x) - log π(y_l|x)/π_ref(y_l|x)])

y_w = 偏好回答, y_l = 不偏好回答
```

## 6. Tokenization 与上下文窗口

### 6.1 Tokenization

LLM 不直接处理文本，而是先将文本切分为 token：

```python
# 示例：中文无人机指令的 tokenization
from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("meta-llama/Llama-3-8B")

text = "请让无人机飞到红色建筑旁边悬停"
tokens = tokenizer.tokenize(text)
print(tokens)
# ['▁请', '让', '无', '人', '机', '飞', '到', '红', '色', '建', '筑', '旁', '边', '悬', '停']
# 中文通常一个字对应一个或多个 token
```

### 6.2 上下文窗口

| 模型 | 上下文长度 | 约等于 | 可容纳内容 |
|------|-----------|--------|-----------|
| GPT-3.5 | 4K | ~3000 字 | 一篇短文 |
| GPT-4 | 128K | ~10 万字 | 一本书 |
| Llama 3.1 | 128K | ~10 万字 | 一本书 |
| Gemini 1.5 Pro | 1M-10M | ~750 万字 | 数部小说 |

**对无人机的意义**：更长的上下文意味着可以将更多的飞行历史、传感器数据、任务描述一次性输入 LLM，获得更好的决策质量。

## 思考题

1. Transformer 的自注意力机制相比 RNN 的循环结构，在处理长序列时有哪些优势和劣势？
2. 为什么 LoRA 微调能在只更新 0.1% 参数的情况下接近全量微调的效果？其背后的直觉是什么？
3. RLHF 对齐过程中的"奖励模型"是如何训练的？它学习的是什么？
4. 如果你要为无人机任务理解微调一个 LLM，你会如何构造训练数据？
5. 上下文窗口从 4K 扩展到 128K 甚至 1M，对无人机应用场景有什么具体影响？

<details>
<summary>参考答案</summary>

**1.** 优势：(a) 并行计算，训练速度快；(b) 直接建模任意两个 token 的关系，不受距离限制；(c) 梯度传播路径短。劣势：(a) 计算和内存复杂度 O(n²)，长序列开销大；(b) 需要位置编码来注入序列顺序信息（相对位置编码可部分缓解）。

**2.** 直觉：微调的本质是在预训练模型已学到的表示空间中做小幅调整。预训练模型的权重矩阵往往是过参数化的，实际的有效维度远小于矩阵的秩。LoRA 用低秩矩阵近似这个调整方向，r=16 意味着只用 16 个方向来表示"需要调整的方向"，这在很多任务上已经足够。

**3.** 奖励模型通过人类对比标注训练：给定一个 prompt，提供两个回答 A 和 B，人类标注哪个更好。奖励模型学习对任意 (prompt, response) 对给出一个标量分数，使得人类偏好的回答获得更高分数。它学习的是人类偏好的隐式表示。

**4.** 训练数据构造：(a) 收集真实无人机操作场景的指令；(b) 人工编写对应的结构化任务计划；(c) 包含多种表达方式（同义改写）；(d) 包含边界情况和安全约束；(e) 格式如 `{"instruction": "巡逻A区域", "output": "1. 起飞\n2. 飞往A区域..."}`。

**5.** 128K 上下文可以容纳完整的飞行日志、多轮对话历史、完整的地图描述和任务规范，LLM 能基于更全面的信息做决策。1M 上下文甚至可以处理完整的视频帧序列，实现对长航时任务的连续理解和规划。

</details>
