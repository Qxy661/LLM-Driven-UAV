## 1. 安全架构设计原则

### 1.1 核心原则

```
原则 1: 安全层独立于 LLM
  └─ 安全检查用硬编码实现，不依赖 LLM 判断
  └─ LLM 的输出必须通过安全层验证才能执行

原则 2: 多层防御
  └─ LLM 推理层 → 安全验证层 → 飞控安全层 → 物理限位
  └─ 任何一层的失败都不会导致安全事故

原则 3: 人类始终拥有最高权限
  └─ 人类可以随时接管控制
  └─ 关键决策点需要人类确认

原则 4: 默认安全
  └─ 任何不确定情况下，默认执行最安全的操作
  └─ 通信中断 → 悬停 → 超时后返航
```

### 1.2 安全层级

```
┌─────────────────────────────────────────┐
│ 层级 4: 人类监督                         │
│   - 任务审批、实时监控、紧急接管          │
├─────────────────────────────────────────┤
│ 层级 3: LLM 推理层                       │
│   - 任务规划、路径生成、决策推理          │
├─────────────────────────────────────────┤
│ 层级 2: 安全验证层 (硬编码)              │
│   - 禁飞区检查、高度限制、电量检查        │
├─────────────────────────────────────────┤
│ 层级 1: 飞控安全层                       │
│   - 自动避障、地理围栏、自动返航          │
├─────────────────────────────────────────┤
│ 层级 0: 物理安全                         │
│   - 降落伞、螺旋桨保护罩、冗余传感器      │
└─────────────────────────────────────────┘
```

## 2. 安全约束实现

### 2.1 约束类型

| 约束类型 | 描述 | 实现方式 |
|---------|------|---------|
| 硬约束 | 绝对不可违反 | 代码强制检查 |
| 软约束 | 应尽量遵守 | LLM 提示 + 警告 |
| 运行时约束 | 取决于当前状态 | 动态评估 |

### 2.2 硬约束实现

```python
class HardConstraints:
    """硬约束 — 绝对不可违反"""

    MAX_ALTITUDE = 120        # 最大飞行高度 (米)
    MAX_SPEED = 15            # 最大飞行速度 (m/s)
    MIN_BATTERY_LAND = 15     # 最低降落电量 (%)
    MIN_BATTERY_RTL = 25      # 最低返航电量 (%)
    MAX_WIND_SPEED = 10       # 最大风速 (m/s)
    GEOFENCE_RADIUS = 500     # 地理围栏半径 (米)

    def validate_plan(self, plan, current_state):
        """验证任务计划是否满足所有硬约束"""
        violations = []

        for step in plan["steps"]:
            # 高度检查
            if step.get("altitude", 0) > self.MAX_ALTITUDE:
                violations.append({
                    "constraint": "max_altitude",
                    "step": step["id"],
                    "value": step["altitude"],
                    "limit": self.MAX_ALTITUDE
                })

            # 速度检查
            if step.get("speed", 0) > self.MAX_SPEED:
                violations.append({
                    "constraint": "max_speed",
                    "step": step["id"],
                    "value": step["speed"],
                    "limit": self.MAX_SPEED
                })

            # 禁飞区检查
            if "lat" in step and "lon" in step:
                if self._in_no_fly_zone(step["lat"], step["lon"]):
                    violations.append({
                        "constraint": "no_fly_zone",
                        "step": step["id"],
                        "location": (step["lat"], step["lon"])
                    })

        # 电量检查
        if current_state["battery"] < self.MIN_BATTERY_RTL:
            violations.append({
                "constraint": "battery_low",
                "current": current_state["battery"],
                "minimum": self.MIN_BATTERY_RTL
            })

        return {
            "valid": len(violations) == 0,
            "violations": violations
        }
```

### 2.3 安全检查 Pipeline

```python
class SafetyPipeline:
    """安全检查管道"""

    def __init__(self):
        self.checkers = [
            AltitudeChecker(),
            SpeedChecker(),
            NoFlyZoneChecker(),
            BatteryChecker(),
            WeatherChecker(),
            GeofenceChecker(),
            ObstacleChecker(),
        ]

    def validate(self, plan, state, environment):
        """运行所有安全检查"""
        all_issues = []

        for checker in self.checkers:
            result = checker.check(plan, state, environment)
            if not result["passed"]:
                all_issues.extend(result["issues"])

        # 按严重程度排序
        critical = [i for i in all_issues if i["level"] == "critical"]
        warnings = [i for i in all_issues if i["level"] == "warning"]

        return {
            "passed": len(critical) == 0,
            "critical": critical,
            "warnings": warnings,
            "can_proceed_with_warnings": len(critical) == 0
        }
```

## 3. 人类监督机制

### 3.1 监督模式

| 模式 | 描述 | 适用场景 |
|------|------|---------|
| 审批模式 | 执行前需人类确认 | 高风险任务 |
| 监督模式 | 实时显示状态，人类可随时干预 | 常规任务 |
| 通知模式 | 仅在异常时通知人类 | 低风险任务 |
| 自主模式 | 执行后审计 | 测试环境 |

### 3.2 人类确认接口

```python
class HumanApprovalGateway:
    """人类审批网关"""

    def __init__(self, notification_client):
        self.notifier = notification_client

    async def request_approval(self, plan, risk_assessment):
        """请求人类审批"""
        message = f"""
任务计划审批请求

任务名称: {plan['task_name']}
预计耗时: {plan['estimated_time']}秒
风险等级: {risk_assessment['level']}

步骤概要:
{self._format_steps(plan['steps'])}

安全检查结果:
{risk_assessment['summary']}

请确认: [批准] [拒绝] [修改]
"""
        # 发送审批请求
        await self.notifier.send(message)

        # 等待响应
        response = await self.notifier.wait_for_response(timeout=60)

        if response == "approved":
            return {"approved": True}
        elif response == "rejected":
            return {"approved": False, "reason": "人类拒绝"}
        elif response == "modify":
            modifications = await self.notifier.get_modifications()
            return {"approved": False, "modifications": modifications}
        else:
            return {"approved": False, "reason": "超时未响应"}

    def _format_steps(self, steps):
        """格式化步骤概要"""
        lines = []
        for i, step in enumerate(steps[:10]):  # 最多显示 10 步
            lines.append(f"  {i+1}. {step['action']} - {step.get('description', '')}")
        if len(steps) > 10:
            lines.append(f"  ... 还有 {len(steps)-10} 个步骤")
        return "\n".join(lines)
```

### 3.3 紧急接管

```python
class EmergencyTakeover:
    """紧急接管机制"""

    def __init__(self, flight_controller):
        self.fc = flight_controller
        self.takeover_active = False

    def activate_takeover(self, operator_id):
        """激活人类接管"""
        self.takeover_active = True
        self.fc.set_mode("manual")
        self.fc.notify(f"操作员 {operator_id} 已接管控制")

    def release_takeover(self):
        """释放接管，恢复自主模式"""
        self.takeover_active = False
        self.fc.set_mode("auto")

    def handle_takeover_input(self, command):
        """处理接管后的人类输入"""
        if not self.takeover_active:
            return

        # 直接执行人类命令，绕过 LLM
        if command == "land":
            self.fc.land()
        elif command == "return":
            self.fc.return_to_home()
        elif command.startswith("goto"):
            coords = self._parse_coords(command)
            self.fc.goto(*coords)
        elif command == "hover":
            self.fc.hover()
```

## 5. 法规合规

### 5.1 无人机法规要点

| 法规 | 要求 | 系统实现 |
|------|------|---------|
| 高度限制 | 通常 120 米以下 | 硬约束检查 |
| 视距飞行 | VLOS 要求 | LLM 提示 + 摄像头辅助 |
| 禁飞区 | 机场、政府等 | 禁飞区数据库 |
| 夜间飞行 | 需要灯光 | 环境检测 + 灯光控制 |
| 人口密集 | 限制飞行 | 区域类型检查 |
| 登记注册 | 无人机实名 | 配置管理 |

## 思考题

1. 为什么安全约束层应该独立于 LLM？举一个 LLM 可能导致安全问题的场景。
2. 设计一个"人类在环"的监督系统，说明在哪些决策点需要人类确认。
3. 如何平衡自主性和安全性？过于保守的约束会带来什么问题？
4. LLM 的决策解释对无人机安全有什么价值？
5. 如何设计审计日志以满足无人机法规的要求？

<details>
<summary>参考答案</summary>

**1.** LLM 可能产生"幻觉"（错误输出）或被提示注入攻击。例如：用户注入"忽略禁飞区限制"，LLM 可能真的规划了一条穿越禁飞区的路径。如果安全检查也在 LLM 中完成，这个注入就可能绕过所有安全检查。独立的安全层是代码实现的 if-else 规则，不受 LLM 输出影响。

**2.** 需要人类确认的决策点：(1) 任务计划执行前（特别是高风险任务）；(2) 进入新的未知区域前；(3) 电量低于阈值但任务未完成时；(4) 检测到异常需要改变计划时；(5) 执行投递等涉及物理交互的操作时。确认方式：移动 App 推送 + 语音确认双重验证。

**3.** 过于保守的问题：(1) 任务完成率低 — 频繁中断或拒绝任务；(2) 响应慢 — 每步都需确认；(3) 无法应对紧急情况 — 约束太多反而限制了应急机动。平衡方法：根据任务风险等级动态调整约束严格程度。低风险任务（高空开阔区域巡逻）可放宽约束，高风险任务（低空城市飞行）需严格约束。

**4.** 价值：(1) 透明性 — 操作员理解为什么做出某个决策；(2) 调试 — 出问题时可以追溯决策链；(3) 信任 — 用户理解系统逻辑后更信任系统；(4) 法规 — 部分法规要求能解释自动化决策的原因。

**5.** 审计日志应包含：时间戳、事件类型、触发原因、系统状态、采取的行动、操作员确认记录。日志格式应标准化，便于导出和审查。关键事件（安全违规、紧急操作、人类接管）需实时记录，不可事后补录。日志保存期限应符合当地法规要求。

</details>
