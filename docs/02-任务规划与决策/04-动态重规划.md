本文档介绍当无人机执行任务过程中遇到意外情况时，如何利用 LLM 进行动态重规划。

---

## 1. 为什么需要动态重规划？

### 1.1 静态规划的局限

```
预先规划: A → B → C → D → E

执行中遇到:
  - B 点发现新障碍物
  - C 点天气突变
  - 电量消耗超预期
  - 用户更改任务目标

静态规划无法应对这些变化 → 需要动态重规划
```

### 1.2 需要重规划的场景

| 触发条件 | 场景示例 | 紧急程度 |
|---------|---------|---------|
| 障碍物出现 | 路线上出现新建筑/车辆 | 高 |
| 天气变化 | 突然起风/下雨 | 中-高 |
| 电量异常 | 消耗速度快于预期 | 高 |
| 传感器故障 | GPS 信号丢失 | 高 |
| 任务目标变更 | 用户发送新指令 | 中 |
| 发现异常 | 巡逻中发现可疑目标 | 中 |
| 禁飞区更新 | 临时禁飞通知 | 高 |
| 通信中断 | 与地面站失去联系 | 高 |

## 2. 重规划架构

### 2.1 事件驱动的重规划框架

```python
class DynamicReplanner:
    """LLM 驱动的动态重规划器"""

    def __init__(self, llm_client, flight_controller):
        self.llm = llm_client
        self.fc = flight_controller
        self.current_plan = None
        self.execution_history = []
        self.monitors = []

    def set_plan(self, plan):
        self.current_plan = plan
        self.execution_history = []

    def monitor_and_replan(self):
        """持续监控并触发重规划"""
        while self.fc.is_flying():
            # 检查所有监控器
            for monitor in self.monitors:
                event = monitor.check()
                if event:
                    self._handle_event(event)

    def _handle_event(self, event):
        """处理异常事件"""
        # 1. 评估事件严重程度
        severity = self._assess_severity(event)

        if severity == "critical":
            # 立即执行应急预案，不等 LLM
            self._execute_emergency(event)
            return

        # 2. 收集当前状态
        state = self._get_full_state()

        # 3. 请求 LLM 重规划
        new_plan = self._llm_replan(event, state)

        # 4. 验证新计划
        if self._validate_plan(new_plan):
            self.current_plan = new_plan
            self._execute_from_current_step()
        else:
            # LLM 计划不可行，使用备选方案
            self._execute_fallback(event)

    def _llm_replan(self, event, state):
        """请求 LLM 重规划"""
        prompt = f"""无人机任务执行中遇到异常，需要重规划。

原始任务计划: {json.dumps(self.current_plan, ensure_ascii=False)}
已执行步骤: {self.execution_history}
当前步骤: {state['current_step']}
异常事件: {json.dumps(event, ensure_ascii=False)}
当前状态:
- 位置: ({state['lat']}, {state['lon']})
- 高度: {state['alt']}m
- 电量: {state['battery']}%
- 风速: {state['wind_speed']}m/s

请生成新的任务计划。要求:
1. 从当前步骤开始重新规划
2. 考虑剩余电量
3. 处理异常事件
4. 尽可能完成原始任务目标
5. 如果无法完成，优先保证安全

输出 JSON 格式的新计划。"""

        return json.loads(self.llm.generate(prompt))
```

## 3. 异常检测

### 3.1 多层级监控

```python
class FlightMonitor:
    """飞行状态监控器"""

    def check(self):
        events = []
        events.extend(self._check_battery())
        events.extend(self._check_altitude())
        events.extend(self._check_geofence())
        events.extend(self._check_weather())
        events.extend(self._check_communication())
        events.extend(self._check_progress())
        return events if events else None

    def _check_battery(self):
        battery = self.fc.get_battery()
        if battery < 15:
            return [{"type": "battery_critical", "level": "critical",
                     "data": {"battery": battery}}]
        elif battery < 30:
            return [{"type": "battery_low", "level": "warning",
                     "data": {"battery": battery}}]
        return []

    def _check_geofence(self):
        pos = self.fc.get_position()
        if self._outside_geofence(pos):
            return [{"type": "geofence_violation", "level": "critical",
                     "data": {"position": pos}}]
        return []

    def _check_progress(self):
        expected = self._get_expected_progress()
        actual = self._get_actual_progress()
        if actual < expected * 0.5:  # 进度严重落后
            return [{"type": "progress_delay", "level": "warning",
                     "data": {"expected": expected, "actual": actual}}]
        return []
```

### 3.2 环境变化检测

```python
class EnvironmentChangeDetector:
    """环境变化检测器"""

    def __init__(self, vlm_client):
        self.vlm = vlm_client
        self.baseline = None

    def set_baseline(self, image):
        """设置基线图像"""
        self.baseline = self._extract_features(image)

    def detect_changes(self, current_image):
        """检测环境变化"""
        current_features = self._extract_features(current_image)

        prompt = f"""比较这两张无人机航拍图像，检测环境变化。

基线图像描述: {self.baseline}
当前图像描述: {current_features}

请识别:
1. 新出现的障碍物
2. 消失的参照物
3. 移动的目标
4. 环境条件变化（光照、天气）
5. 对飞行安全的影响评估

输出 JSON 格式。"""

        changes = json.loads(self.vlm.generate(prompt))

        if changes.get("safety_impact") in ["high", "critical"]:
            return {
                "type": "environment_change",
                "level": "warning",
                "data": changes
            }
        return None
```

## 4. 重规划策略

### 4.1 策略矩阵

| 异常类型 | 策略 | LLM 参与度 | 响应时间要求 |
|---------|------|-----------|------------|
| 电量严重不足 | 立即返航 | 无需 LLM | <1秒 |
| GPS 丢失 | 悬停等待 | 低 | <2秒 |
| 新障碍物 | 局部重规划 | 高 | <5秒 |
| 天气变化 | 任务调整 | 高 | <10秒 |
| 任务目标变更 | 全局重规划 | 高 | <30秒 |
| 通信中断 | 自主决策 | 中 | <5秒 |

### 4.2 局部 vs 全局重规划

```
局部重规划: 只修改当前步骤附近的航点
  原始: A → B → C → D → E
  障碍: B 附近出现障碍物
  重规划: A → B' → C' → D → E (只改 B 和 C 附近)

适用: 障碍物、小范围环境变化

全局重规划: 重新生成整个任务计划
  原始: 巡逻 A 区域 → 巡逻 B 区域 → 巡逻 C 区域
  变更: B 区域发现可疑目标，需要重点检查
  重规划: 巡逻 A 区域 → 详细检查 B 区域 → 简化 C 区域

适用: 任务目标变更、重大环境变化
```

## 5. 通信中断时的自主决策

### 5.1 离线自主模式

```python
class OfflineAutonomyManager:
    """通信中断时的自主决策管理"""

    # 优先级决策规则 (硬编码，不依赖 LLM)
    PRIORITY_RULES = {
        "battery_critical": {"action": "return_to_home", "priority": 1},
        "geofence_violation": {"action": "return_to_home", "priority": 1},
        "obstacle_imminent": {"action": "emergency_avoid", "priority": 1},
        "mission_complete": {"action": "return_to_home", "priority": 2},
        "communication_lost": {"action": "hover_and_wait", "priority": 3},
    }

    def handle_communication_loss(self, state, timeout=30):
        """处理通信中断"""
        # 1. 先悬停等待
        self.fc.hover(duration=timeout)

        # 2. 等待超时后，根据状态决定行动
        if state["battery"] < 30:
            return self._return_to_home()

        if state["current_step"] == "last_step":
            return self._return_to_home()

        # 3. 如果有边缘 LLM，尝试自主重规划
        if self.edge_llm_available:
            return self._edge_replan(state)

        # 4. 否则按预设规则执行
        return self._execute_safe_default(state)

    def _execute_safe_default(self, state):
        """执行安全默认行为"""
        # 悬停 → 尝试重连 → 超时后返航
        self.fc.hover(duration=60)
        if not self._try_reconnect():
            self._return_to_home()
```

class ReplanExperienceLogger:

        """检索相似的重规划经历"""
        query = f"事件类型: {event['type']}, 数据: {event['data']}"
        return self.vector_store.similarity_search(query, k=k)

## 思考题

1. 在电量严重不足的情况下，为什么建议使用硬编码规则而不是 LLM 决策？
2. 设计一个场景：无人机在执行巡逻任务时遇到强风，LLM 应该如何重规划？
3. 如何处理 LLM 重规划失败（生成的计划不可行）的情况？
4. 在多无人机编队中，一架无人机需要重规划时，如何协调其他无人机？
5. 如何利用历史重规划经验改进未来的决策？

<details>
<summary>参考答案</summary>

**1.** 电量严重不足是安全关键场景，需要毫秒级响应。LLM 推理需要数秒，且可能产生不可靠的结果（幻觉）。硬编码规则（电量 < 15% → 立即返航）是确定性的、可验证的、无延迟的。在安全关键场景中，确定性比智能性更重要。

**2.** 场景：巡逻中风速从 5m/s 突增到 12m/s。LLM 重规划策略：(1) 降低飞行高度（减少风阻）；(2) 缩短剩余巡逻路线（减少暴露时间）；(3) 优先完成关键区域；(4) 降低飞行速度以保持稳定；(5) 如果风速持续增大，提前返航。

**3.** 多层降级：(1) 用温度=0 重新请求 LLM（更确定性的输出）；(2) 使用更简单的 prompt（只关注安全约束）；(3) 使用预定义的备选计划模板；(4) 最终降级为硬编码安全规则（悬停→返航）。

**4.** 协调策略：(1) 重规划的无人机通知编队其他成员；(2) 其他无人机调整自己的路径以保持编队间距；(3) 如果重规划导致任务变更，由任务总管 LLM 重新分配任务；(4) 关键原则：任何一架无人机的安全优先于编队任务。

**5.** 将每次重规划经历存入向量数据库，包含事件类型、环境条件、采取的行动和结果。下次遇到类似事件时，先检索历史经验，作为 LLM 重规划的参考。长期来看，可以用这些数据微调边缘 LLM，提升重规划质量。

</details>
