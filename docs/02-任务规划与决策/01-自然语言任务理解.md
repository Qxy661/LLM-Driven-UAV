本文档介绍如何让 LLM 理解用户的自然语言指令，将其转化为结构化的无人机任务命令，包括意图解析、约束提取和安全检查。

## 1. 自然语言任务理解的挑战

### 1.1 指令的多样性

同一任务可以用多种方式表达：

| 用户表达 | 实际意图 |
|---------|---------|
| "起飞" | 起飞到默认高度 |
| "飞高一点" | 增加当前高度 |
| "去看看那边什么情况" | 飞往用户指向的方向并拍照 |
| "帮我巡逻一圈" | 按预设路线或当前区域巡逻 |
| "有危险赶紧回来" | 立即返航 |
| "东北角那个红房子旁边停一下" | 飞到特定位置悬停 |

### 1.2 歧义与模糊性

自然语言天然存在歧义：

```
模糊指令: "飞到大楼旁边"

需要澄清:
- 哪栋大楼？(如果有多个)
- 哪一侧？(东/南/西/北)
- "旁边"是多远？(5米？20米？)
- 什么高度？
```

### 1.3 隐含约束

用户未明说但必须遵守的规则：

```
用户: "飞到市中心上空拍几张照片"

隐含约束:
- 市中心可能是禁飞区 → 需要查询禁飞区数据库
- 人口密集区域 → 高度和安全距离限制
- "几张"是多少？ → 需要默认值或询问
- 什么时间段？ → 夜间飞行限制
```

```python
class IntentParser:
    """自然语言意图解析器"""

    def __init__(self, llm_client):
        self.llm = llm_client

    def parse(self, user_input: str) -> dict:
        prompt = f"""你是一个无人机指令解析专家。
请分析用户的自然语言指令，提取以下信息：

1. intent: 主要意图（从预定义类别中选择）
2. parameters: 意图参数
3. constraints: 约束条件（显式和隐式）
4. ambiguity: 需要澄清的模糊点
5. confidence: 解析置信度 (0-1)
6. safety_flags: 安全相关标记

预定义意图类别:
- takeoff, land, hover, return_to_home
- goto_location, follow_route, orbit, track
- capture_photo, record_video, patrol, scan_area
- where_am_i, status_check, battery_check
- emergency_land, abort_mission

用户指令: "{user_input}"

请以 JSON 格式输出。"""

        response = self.llm.generate(prompt)
        return json.loads(response)
```

## 3. 实体提取

### 3.1 无人机领域实体类型

| 实体类型 | 示例 | 提取方式 |
|---------|------|---------|
| 位置 | "教学楼A"、"篮球场" | 命名实体识别 + 知识库匹配 |
| 坐标 | "北纬31.23度" | 正则表达式 |
| 高度 | "20米"、"高一点" | 数值提取 + 相对值推理 |
| 方向 | "东面"、"左边" | 方向词典 |
| 时间 | "5分钟后"、"明天" | 时间解析器 |
| 动作 | "拍照"、"巡逻" | 意图分类 |
| 数量 | "3张照片"、"一圈" | 数值提取 |
| 目标 | "红色车辆"、"可疑人员" | 目标描述提取 |

### 3.2 位置实体解析

```python
class LocationResolver:
    """将自然语言位置描述解析为坐标"""

    def __init__(self, landmark_db, llm_client):
        self.landmarks = landmark_db  # 已知地标数据库
        self.llm = llm_client

    def resolve(self, location_desc: str) -> dict:
        # 1. 尝试精确匹配已知地标
        match = self._exact_match(location_desc)
        if match:
            return {"type": "landmark", "coordinates": match}

        # 2. 尝试模糊匹配
        fuzzy = self._fuzzy_match(location_desc)
        if fuzzy and len(fuzzy) == 1:
            return {"type": "landmark", "coordinates": fuzzy[0]}
        elif fuzzy and len(fuzzy) > 1:
            return {"type": "ambiguous", "candidates": fuzzy}

        # 3. 使用 LLM 推理
        return self._llm_resolve(location_desc)

    def _exact_match(self, desc):
        return self.landmarks.get(desc)

    def _fuzzy_match(self, desc):
        from difflib import get_close_matches
        return get_close_matches(desc, self.landmarks.keys(), n=3, cutoff=0.6)

    def _llm_resolve(self, desc):
        prompt = f"""用户描述了一个位置: "{desc}"
已知地标: {list(self.landmarks.keys())}
当前位置: ({self.current_lat}, {self.current_lon})

请推断用户最可能指的是哪个位置，或给出相对位置描述。"""
        return self.llm.generate(prompt)
```

## 4. 约束提取

### 4.1 约束类型

```
显式约束 (用户明确说出):
├── "飞到20米高度"         → 高度约束 = 20m
├── "用慢速飞"             → 速度约束 = slow
├── "只拍北面"             → 方向约束 = north
└── "5分钟内完成"          → 时间约束 = 300s

隐式约束 (需要系统推断):
├── 电量 < 20% 时          → 必须返航
├── 风速 > 10m/s           → 不建议起飞
├── 夜间                   → 需要灯光/夜视
├── 人口密集区             → 增加安全高度
└── 禁飞区                 → 绝对禁止进入
```

### 4.2 约束提取器

```python
class ConstraintExtractor:
    """从解析结果中提取和补充约束"""

    SAFETY_RULES = {
        "max_altitude": 120,       # 最大飞行高度 (米)
        "min_battery_landing": 20, # 降落最低电量 (%)
        "min_battery_rtl": 30,     # 返航最低电量 (%)
        "max_wind_speed": 10,      # 最大风速 (m/s)
        "no_fly_zones": [],        # 禁飞区列表
        "min_visibility": 1000,    # 最小能见度 (米)
    }

    def extract(self, parsed_intent, flight_state):
        constraints = {}

        # 1. 从意图中提取显式约束
        if "altitude" in parsed_intent.get("parameters", {}):
            constraints["altitude"] = parsed_intent["parameters"]["altitude"]

        # 2. 添加安全约束
        constraints["safety"] = self._apply_safety_rules(flight_state)

        # 3. 添加环境约束
        constraints["environment"] = self._check_environment(flight_state)

        # 4. 检查禁飞区
        if "target" in parsed_intent.get("parameters", {}):
            nfz_check = self._check_no_fly_zone(
                parsed_intent["parameters"]["target"]
            )
            if nfz_check["in_nfz"]:
                constraints["blocked"] = True
                constraints["reason"] = f"目标位于禁飞区: {nfz_check['zone_name']}"

        return constraints

    def _apply_safety_rules(self, state):
        rules = {}
        if state["battery"] < self.SAFETY_RULES["min_battery_rtl"]:
            rules["force_rtl"] = True
            rules["reason"] = "电量不足，必须返航"
        if state["wind_speed"] > self.SAFETY_RULES["max_wind_speed"]:
            rules["warning"] = "风速过大，建议推迟任务"
        return rules
```

### 5.2 安全检查实现

```python
class SafetyChecker:
    """安全检查层 — 硬编码规则，不依赖 LLM"""

    def check(self, task_plan, flight_state, environment):
        issues = []

        # 高度检查
        for step in task_plan["steps"]:
            alt = step.get("altitude", 0)
            if alt > 120:
                issues.append({
                    "level": "critical",
                    "msg": f"步骤 '{step['action']}' 高度 {alt}m 超过120m限制"
                })

        # 禁飞区检查
        for step in task_plan["steps"]:
            if "lat" in step and "lon" in step:
                if self._in_no_fly_zone(step["lat"], step["lon"]):
                    issues.append({
                        "level": "critical",
                        "msg": f"步骤 '{step['action']}' 目标在禁飞区内"
                    })

        # 电量检查
        estimated_time = task_plan.get("estimated_time", 0)
        current_battery = flight_state["battery"]
        consumption_rate = self._estimate_consumption(task_plan)
        remaining_after = current_battery - (estimated_time * consumption_rate)
        if remaining_after < 20:
            issues.append({
                "level": "warning",
                "msg": f"任务完成后预计电量 {remaining_after:.0f}%，建议缩短任务"
            })

        # 天气检查
        if environment["wind_speed"] > 10:
            issues.append({
                "level": "warning",
                "msg": f"当前风速 {environment['wind_speed']}m/s，注意安全"
            })

        return {
            "passed": not any(i["level"] == "critical" for i in issues),
            "issues": issues
        }
```

## 6. 多轮澄清对话

### 6.1 澄清策略

当指令存在歧义时，系统应主动发起澄清：

```python
class ClarificationManager:
    """管理多轮澄清对话"""

    def __init__(self, llm_client):
        self.llm = llm_client

    def needs_clarification(self, parsed_intent):
        """判断是否需要澄清"""
        if parsed_intent["confidence"] < 0.7:
            return True
        if parsed_intent.get("ambiguity"):
            return True
        if self._missing_critical_params(parsed_intent):
            return True
        return False

    def generate_clarification(self, parsed_intent, user_input):
        """生成澄清问题"""
        prompt = f"""用户说: "{user_input}"
解析结果: {json.dumps(parsed_intent, ensure_ascii=False)}

请生成一个简短的澄清问题，帮助理解用户的真实意图。
要求：一次只问一个最重要的问题，语气友好。"""

        return self.llm.generate(prompt)

    def _missing_critical_params(self, intent):
        """检查关键参数是否缺失"""
        required = {
            "goto_location": ["target"],
            "capture_photo": [],  # 无必需参数
            "patrol": ["route_or_area"],
        }
        intent_type = intent.get("intent")
        needed = required.get(intent_type, [])
        params = intent.get("parameters", {})
        return any(p not in params for p in needed)
```

```python
def extract_chinese_entities(text):
    # 使用 jieba 分词
```

4. 如何处理用户的语音识别错误（如"飞到脚学楼"应为"飞到教学楼"）？
5. 设计一个端到端的自然语言任务理解系统，从接收指令到输出可执行的任务计划。

<details>
<summary>参考答案</summary>

**1.** 设计原则：(1) 层级化 — 按飞行控制、导航、任务、查询、应急分大类；(2) 可扩展 — 允许添加新意图；(3) 领域特定 — 结合无人机操作术语；(4) 多标签 — 一个指令可能包含多个意图（"飞到A拍照然后回来"包含3个意图）。建议使用 LLM 做意图分类而非传统 NLU，因为 LLM 天然理解多样化表达。

**2.** 策略：(1) 如果有指向设备（如手指追踪），直接使用指向方向；(2) 如果有历史上下文（之前提到过某个位置），推断可能目标；(3) 如果有当前位置和已知地标，列出可能的候选让用户选择；(4) 最保守的方案：悬停在当前位置，请求用户明确指定。关键是不要猜测 — 错误的猜测可能导致危险。

**3.** LLM 可能"幻觉"或被提示注入攻击绕过。安全检查应该是确定性的：(1) 代码实现的 if-else 规则；(2) 不接受外部输入修改；(3) 具有最高优先级（即使 LLM 说可以，安全层不通过也不执行）。例如：高度 > 120m 的检查必须是代码层面的硬限制，不能依赖 LLM 判断。

**4.** 处理策略：(1) 使用 ASR 的置信度分数，低置信度时触发确认；(2) 使用编辑距离或拼音相似度做纠错（"脚学楼" → "教学楼"）；(3) 利用无人机任务的领域知识缩小候选范围；(4) LLM 本身有一定的纠错能力，可在 prompt 中要求"识别可能的语音识别错误"。

**5.** 端到端流程：(1) 语音/文字输入 → ASR（如果是语音）；(2) 文本预处理（纠错、标准化）；(3) 意图解析（LLM）；(4) 实体提取（LLM + 规则）；(5) 约束提取（规则引擎）；(6) 安全检查（硬编码）；(7) 澄清对话（如有歧义）；(8) 任务计划生成（LLM）；(9) 人类确认（可选）；(10) 输出结构化任务计划。

</details>
